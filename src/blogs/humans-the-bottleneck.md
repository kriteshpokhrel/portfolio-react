*Part 2 of **Fast Code, Slow Engineering**, a short series on what AI agents are actually speeding up — and what they aren't.*

> If writing code was never the real constraint, then making it faster just moves the pressure somewhere else. This post is about where it lands.

## The Constraint Moves

Humans, currently the rate-limiters of this code overload, might soon become the bottlenecks of the process. To deal with the high volume of code, reviews get rushed, patterns that would have been caught get missed. Architectural drift accumulates across dozens of pull requests, and the collective mental model the team builds over time, the shared sense of why things are the way they are, never fully forms.

So the honest question is whether we can accelerate these processes at the same rate. Can we 10X code review? Can we 10X the processes that build the requirements, test the impact of new features on the application?

## What Comes Next

AI has not reached every corner of where developers work, at least not yet. Most teams are still in early stages. But the direction is clear. This is not going away, and the pace is only picking up.

Which means the adaptation has to be intentional. Not just making use of these tools, but genuinely rethinking the process, team structure and where human judgment must be.

There is a deeper shift happening in how codebases are maintained and software gets built. The software we write will increasingly need to be built with agents in mind. AI native repositories with better documentation, more modular boundaries, codebases that are easier for an agent to navigate and contribute to without breaking things.
