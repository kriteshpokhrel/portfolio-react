*Part 1 of **Fast Code, Slow Engineering**, a short series on what AI agents are actually speeding up — and what they aren't.*

> As a developer navigating this rapidly shifting AI landscape, I still have conflicting thoughts on where the new development process and ecosystem will eventually settle. In this article, I will try to show a fuller, more opinionated and experienced version of the "10X AI Agent productivity" story.

## The 10X Claim

Every developer ecosystem right now is going through what feels like a genuine transformation. A year or two ago, using Copilot felt like magic — a quiet suggestion here, an autocomplete there — and now we have AI agents writing code at unimaginable speeds, with magnitudes of productivity projections being thrown around that are hard to ignore. 5X, 10X, sometimes even more. The demos of "non-technical" people programming back it up, and the output velocity looks real.

While I enjoy this, a question keeps coming up in the back of my mind. Are we actually engineering 10X faster, or are we just generating code 10X faster? Because those are not the same thing.

Engineering is programming integrated over time. This is the skill that every developer continuously works on building, and uses to make long lasting, scalable systems. It is not something we run after. Engineering is accumulated across months and years.

Software is more of a liability than an asset. Every line of code you ship is a line that someone has to maintain, debug, understand and eventually change. So if we are generating significantly more code than before, we are not creating more value. We are potentially creating more surface area to break, more context to carry, and more decisions that compound over time. 10X code without engineering is not 10X productivity but 10X liability.

## The Development Ecosystem Is Bigger Than Writing Code

When people talk about developer productivity gains, they tend to picture a single component. A developer typing less and AI typing more. But writing code is a fraction of what happens inside a software team.

Think of what surrounds code. Code review, static analysis, architecture decisions, performance testing. These are not bureaucratic overhead, but where a lot of engineering happens. The principles that make your software great do not emerge from writing code, they get enforced through these engineering disciplines that build over time.

So when we celebrate 10X code generation, we are measuring the one part of the process that was arguably never the real constraint. The velocity is real, but it lands on top of an ecosystem that has not sped up with it — and that gap is where the interesting problems start.
