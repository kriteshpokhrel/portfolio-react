*Part 1 of **AI, As I See It**, a personal series on what AI agents are really changing about how we build software — and what they aren't.*

> As a developer navigating this rapidly shifting AI landscape, I still have conflicting thoughts on where the new development process and ecosystem will eventually settle. In this article, I will try to show a fuller, more opinionated and experienced version of the "10X AI Agent productivity" story.

## The 10X Claim

Every developer ecosystem right now is going through what feels like a genuine transformation. When I first started using Copilot a year or two ago, it felt like magic - autocomplete suggestions that could complete the functions — and now we have AI agents writing code at unimaginable speeds, with magnitudes of productivity projections being thrown around that are hard to ignore. 5X, 10X, sometimes even more. The demos of "non-technical" people programming back it up, and the output velocity looks real.

While I enjoy this, a question keeps coming up in the back of my mind. Are we actually engineering 10X faster, or are we just generating code 10X faster? Because those are not the same thing.

Engineering is programming integrated over time. This is the skill that every developer continuously works on building, and uses to make long lasting, scalable systems. Engineering is accumulated across months and years.

Software is more of a liability than an asset. Every line of code you ship is a line that someone has to maintain, debug, understand and eventually change. So if we are generating significantly more code than before, we are not creating more value. We are potentially creating more surface area to break, more context to carry, and more decisions that compound over time. 10X code without engineering is not 10X productivity but 10X liability. And all the code we write, it has to be deployed somewhere. Are we really ready to deploy 10X code than before? Do our processes really support this?

## The Development Ecosystem Is Bigger Than Writing Code

When people talk about developer productivity gains, they tend to picture a single thing: a developer typing less and AI typing more. But writing code is only a fraction of what actually happens inside a software team, and it took me a while to really feel the difference.

Think of what surrounds code. Code review, static analysis, architecture decisions, performance testing. These are not bureaucratic overhead, but where a lot of engineering happens. The principles that make your software great do not emerge from writing code, they get enforced through these engineering disciplines that build over time.

So when we celebrate 10X code generation, we are measuring the one part of the process that was arguably never the real constraint. The velocity is real, but it lands on top of an ecosystem that has not sped up with it — and that gap is where the interesting problems start.
